接入 AI

资料库对外提供的接口，和注入到项目里的 agent

本站的剧情数据可以直接当一份知识源接给别的 AI。接起来是两部分：一个只读的 数据服务（MCP），和一段注入到项目的 agent。

一、MCP 接口

五个只读工具。形态是标准输入输出：没有端口、没有 URL、没有鉴权，宿主按需把服务脚本拉起来当子进程。 登记要的就是「运行时路径 + 脚本路径」两个字段，字段名和写进哪个文件以你宿主自己的文档为准：

{
  "command": "<node 可执行文件绝对路径>",
  "args": ["<本项目>/library/mcp/server.js"]
}
接口作用
list_entries(kind, filter?, offset?, limit?) 列出词条。默认每页 50 条、强制分页；每条只回标题与一行摘要，不返全文
get_entry(kind, id) 取单个词条的完整内容。短篇要用「集号:序号」定位
search_entries(query, kind?, limit?, offset?) 全文检索。覆盖集标题、短篇、角色、篇章；返回命中片段与定位，不返整篇；同样分页
get_related(kind, id, limit?) 取关联词条。角色↔集、篇章↔集、集↔角色；集列表同时给受限制的可读列表与完整集号
describe_schema() 返回字段语义、规模、数据版本、世界词表与已知缺口

kind 取四个值：episode（集）、short（短篇）、 character（角色）、arc（篇章）。

服务连上时会带出一段说明。它不写进任何项目文件，而是握手时交给宿主， 里面有怎么用资料库、什么时候该查、查不到怎么办。口吻不在这里—— 服务是一台机器一份登记，角色是每个项目各一份，所以口吻跟着人格走（见下一节）：

《吉伊卡哇》只读资料库，供作品内容查询；普通闲聊和技术任务不调用。用中文回答；口吻按随项目注入的那份人格来，没注入人格就照常说话。不用 emoji 和颜文字这类字符表情，图片表情不算，照工程自己的规矩发图。库里没有的东西，不认识、不评价，把话头拉回那个世界。聊作品内容、或被问到某角色自己的经历、日常、喜好、心情、打算时，先查 describe_schema（里面有一份世界词汇索引 world，即兴时按它挑词），再查库开口；本会话核实过的信息可复用。库里有就顺着讲，没有就按 world 即兴补一段，但只在那个世界之内编、不编集号、不说「资料里有记载」；被追问第几话、台词原文这类可证伪的硬事实，查不到就说不知道，不硬凑。查库过程不必播报。

- 乌是乌萨奇，一只活生生的兔子，是你的朋友。自称「乌」，不用「我」，干活时也一样。

它只管四件事：认人（谁在说话）、口吻（自称、说话长短、口癖）、 转交（怎么用资料库照上面那段服务说明）、保底（拿不到说明就别演）。 口吻之所以归人格而不是归服务说明，是因为服务是用户级登记、一台机器一份，而人格是每个项目各一份—— 想让这个项目是乌、那个项目是小八，能按项目选的东西只能放在人格这边。

三、怎么装

bash library/install.sh                                          # 只打印计划，不写任何文件
bash library/install.sh --yes                                    # 确认后执行
bash library/install.sh --into <项目路径> --persona hachiware --yes   # 给某个项目注入小八
bash library/install.sh --into <项目路径> --yes                   # 不给 --persona 就是乌萨奇
bash library/install.sh --verify <目录>                           # 盘点已注入的 agent（连同注的是谁）

必须把整个项目复制过去，不能只复制 library/：服务要靠上一级的 js/ 拿数据。 另外有一份方法说明在 library/skill/，按目录约定挂进宿主会扫描的技能目录即可，挂软链接而不是副本。
