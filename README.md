# 吉伊卡哇 · 中文剧情资料站 + MCP 资料库

《吉伊卡哇》（ちいかわ）动画的中文剧情资料：日方放送回 **第 1–345 话**、**480 个短篇**、**990 条台词 / 动作记录**、**30 个角色**、**40 个篇章**。

同一份数据，两种用法：

- **静态站** —— 零依赖，直接用浏览器打开，查剧集、篇章、角色、台词。
- **MCP 资料库** —— 一个只读的数据服务，让支持 MCP 的宿主（任何模型、任何客户端）把这份资料当知识源用。

> 本仓库原名 `chiikawa-site`，现名 `chiikawa-mcp`；旧地址会跳转到新地址，git 历史没有断。

│   ├── app.js          渲染、筛选、检索
│   ├── nav.js          导航高亮

├── assets/images/
└── library/
    ├── README.md       资料库契约、设计取舍、数据缺口（建议先读这份）

站点与资料库共用 `js/` 下的同一份数据，没有 JSON 副本、没有数据库、没有中间层。改一行数据，两边同时生效。

## 打开站点

纯静态，没有构建步骤：

```bash
python3 -m http.server 8000
# 浏览器打开 http://127.0.0.1:8000
```

也可以用任意静态文件服务器。剧情数据随页面脚本一起加载，断网也能看。

## 接入资料库（MCP）

需要 Node.js（只用内置模块，**不用装任何包**）。先看安装器打算做什么，再执行：

```bash
bash library/install.sh          # 只打印计划，不写文件
bash library/install.sh --yes    # 按计划登记
```

安装器会校验数据、跑一次真实握手自检，然后把服务与说明登记到宿主对应位置；撤销用 `--uninstall --yes`。只想手工登记的话，`bash library/install.sh --print` 会输出可直接粘贴的注册信息。

**服务与方法说明是用户级的**（装一次，本机所有项目都能用），**人格是按项目注入的**，一个项目选一个角色：

```bash
bash library/install.sh --into <项目路径> --yes                     # 注入乌萨奇（默认）
bash library/install.sh --into <项目路径> --persona hachiware --yes  # 注入小八
```

角色名单从 `library/persona/` 现取，加一个角色就是新建一份 `<名字>-persona.md`。同一个服务能同时伺候两个项目、各演各的——`--verify` 会告诉你每个项目注的是谁。

服务是 **stdio 形态**：没有端口、没有 URL、没有鉴权，宿主按需把 `server.js` 拉起来当子进程。登记形状大致是：

```json
{
  "command": "<node 可执行文件绝对路径>",
  "args": ["<本项目绝对路径>/library/mcp/server.js"]
}
```

字段名与配置文件位置以宿主自己的文档为准。五个只读工具：

| 工具 | 作用 |
|---|---|
| `list_entries(kind, filter?, offset?, limit?)` | 列词条；**强制分页**，默认 50，每条只回摘要 |
| `get_entry(kind, id)` | 取单个词条全文；短篇用 `(episode_id, index)` 定位 |
| `search_entries(query, kind?, limit?, offset?)` | 全文检索，默认 40 条，回命中片段与定位 |
| `get_related(kind, id, limit?)` | 取关联词条（角色↔集、篇章↔集、集↔角色） |
| `describe_schema()` | 字段语义、数据版本、世界词表、已知缺口 |

接口契约、摆放原则与设计理由都在 [`library/README.md`](library/README.md)。

## 用数据前必须知道的几件事

- **磁盘读取顺序 ≠ 集号顺序。** 装载后必须显式按 `id` 排序，否则全库乱序，而且不报错。
- **`list_entries` 必须分页。** 345 集一次全吐出去是十万 token 级灾难；检索同理，默认只给一页。
- **角色的 `eps` 是代表性出场，不是全集。** 30 个角色里有 11 个明显偏少（如吉伊卡哇声明 9 集，并集 296 集）；服务层用「声明 ∪ 台词可证 ∪ 动作可证」取并集。
- **篇章的 `start/end` 与 `episodes[].a` 语义不同。** 前者是主体连续区间，后者含呼应 / 回访集；按篇章查集要取「区间 ∪ 反查」。
- **台词是要点式复述，不是逐字字幕。** 用来定位「那句话在第几话」，准确内容以正片为准。
- **短篇概要分可信度 A / B。** A 有公开资料支撑，B 是依据标题与设定整理的框架，细节可能有出入。来源与分级说明见 [about.html](about.html)。

数据现状、每个已知缺口的稳定 id，以及运行时自检结果，都在 `describe_schema()` 的返回里；文字版在 [`library/README.md`](library/README.md) 的「数据现状」一节。

## 检查更新

人格这一层是「复制进目标项目」的注入方式，副本不会自己跟上模板。安装器提供了只读盘点：

```bash
bash library/install.sh --verify <项目路径> --verify <另一个项目路径>
```

它会报出每个位置是「一致 / 已过期 / 无登记」，并给出更新命令。

这是个人整理的粉丝资料站，与官方无关。站内作品标识与角色图像来自公开渠道，仅用于标识与索引，不用于商业用途；逐集概要与台词复述为本项目撰写整理，不是官方文本。
